# e3dp 개발 지침

지침(규칙)만 이 파일에 둔다. 절차·명령·접속 정보는 스킬(`.claude/skills/`)에 둔다.

## 스킬 목록
| 스킬 | 내용 | 사용 시점 |
|---|---|---|
| `e3dp-build` | PC-장치 마운트, `make clean all`, 빌드 기준값, 오류 디버깅 | 소스 수정 후 컴파일·장치 확인 |
| `e3dp-test` | 테스트 구성(PC 시뮬레이터 + 보드 DP), 폴더, 실행 명령, 리포트 | 테스트 작성·실행 |
| `e3dp-ref-device` | 기준 장치(구 환경) 접속 정보, 읽기 전용 절차, 동작 비교 | 구 환경 확인·비교 |

## 프로젝트
- 대상: E3-DP 소스. Raspberry Pi 3 (ARMv7 32bit, Debian) 장치용 C/C++ 프로젝트. 기존에는 NanoPi + Ubuntu 16.04에서 실행.
- 소스: `e3dp.2.1/` (git 저장소). 루트 Makefile이 `lib/*`, `src/*` 순서로 빌드.
- 작업 방식: 소스 수정은 PC, 컴파일·동작 확인은 장치. 이 폴더는 장치 `/home/e3dp`와 CIFS 마운트로 연결.
- 작업 폴더
  - `tasks/`: 작업 단위 체크리스트
  - `tests/`: Python 테스트
  - `e3dp.2.1/docs/`: 소스 문서
- 용어
  - 보드: 컴파일·실행 확인용 Raspberry Pi 3 장치
  - 기준 장치: 구 환경(NanoPi, Ubuntu 16.04)으로 동작하는 연구소 보관 장치. 같은 소스의 바이너리가 실행되며 동작 비교의 기준
  - task: 한 가지 작업의 목표·사실·체크리스트를 적은 md 파일

## 세션 시작 시
1. `tasks/` 확인. 파일명이 `_done.md`로 끝나지 않는 파일이 진행 중 task.
2. 진행 중 task의 체크리스트에서 첫 `[ ]` 항목부터 이어서 진행.
3. 진행 중 task가 없고 새 작업이면 task 파일부터 생성.

## Task 관리
- 위치: `tasks/`
- 파일명: `NNN_task_작업제목.md` (NNN = 3자리, 기존 최대값+1)
- 완료 시 `NNN_task_작업제목_done.md`로 이름 변경. 내용 이동·삭제 금지.
- 새 세션의 AI가 해당 파일만 보고 이어서 작업할 수 있게 쓴다.
- 코드 수정 작업은 착수 전 task 생성이 원칙. 1줄 수정 등 사소한 작업은 생략 가능.

### 템플릿
```
# NNN 작업제목
목표: 한 줄
상태: 진행중 | 보류 | 완료

## 사실 (확인된 것만)
- 항목

## 체크리스트
- [x] 완료 항목
- [ ] 다음 항목 (대상 파일/명령 명시)

## 결정/미정
- 결정: 내용
- 미정: 질문

## 테스트
- 추가/수정한 테스트 파일, 실행 명령, 결과

## 참조
- 경로
```

### 갱신 규칙
- 항목 완료 즉시 `[x]` 체크. 세션 종료 전 일괄 갱신 금지.
- 작업 중 확인한 사실·결정은 즉시 task에 기록.
- 하위 작업은 같은 파일 체크리스트에 추가. 별도 주제면 새 task.
- 전 항목 완료 + 테스트 통과 시 상태를 `완료`로 바꾸고 `_done.md`로 이름 변경.

### 문체
- 개조식. 짧은 구, 명사형 종결(~함, ~임).
- 수식어·형용사·강조어(핵심, 매우, 가장 등) 금지. 장황함 금지.
- 추측과 사실 구분. 확인 안 된 내용은 "사실"에 쓰지 않는다.
- 수치·파일 경로·명령어로 쓴다.

## 테스트 규칙
- 언어·도구: Python 3, pytest. 방식·폴더·실행은 스킬 `e3dp-test`.
- 파일명 `test_<대상>.py`, 함수명 `test_<동작>_<조건>`.
- 마커: 보드 필요 `device`, 기준 장치 필요 `ref`, 장시간 `slow`. 마커 없는 테스트는 보드 없이 실행 가능해야 한다.
- 테스트는 서로 독립. 실행 순서에 의존하지 않는다. 보드 상태를 바꾸면 종료 시 원복.
- 버그 수정 시 재현 테스트를 먼저 작성하고 실패를 확인한 뒤 수정한다.
- 신규 함수·프로토콜 변경에는 테스트를 같이 추가한다. 레거시 코드는 수정하는 부분만 커버한다.
- 접속 정보(IP, 계정, 비밀번호)는 소스·테스트 코드·task에 쓰지 않는다. 환경 변수 또는 git 제외 파일(`tests/local.env`)에서 읽는다.
- 임시 파일·산출물은 `tests/out/`에 두고 git 제외.
- 소스에 디버그 출력을 추가할 때 `#ifdef E3DP_TEST_TRACE`로 감싸 기본 빌드에서는 끈다. 동작 로직은 바꾸지 않는다.

## 코딩 규칙 (C/C++)
### 일반
- 기존 스타일에 맞춘다(K&R, 탭 들여쓰기, 기존 네이밍). 파일 전체 재포맷 금지.
- 요청 범위 밖 리팩터링 금지. 한 커밋에 한 가지 변경.
- 파일 인코딩은 기존 파일 유지(소스 내 한글 주석 포함). 인코딩 변환 금지.
- 주석은 기존 밀도에 맞춘다. 자명한 주석 금지. "왜"가 필요한 곳만.

### 32bit ARM 대상
- 레거시 코드는 `int`, `long`, 포인터가 4바이트라는 가정이 있다. 신규 코드는 `<stdint.h>` 고정폭 타입(`uint32_t` 등) 사용.
- 네트워크·파일 구조체는 패딩과 바이트 순서(endian)를 확인한다. `memcpy`/`sizeof` 가정이 바뀌는 수정은 task에 기록.
- 구조체 크기를 바꾸면 이를 읽는 모든 프로세스(공유 메모리, 소켓, 파일)를 함께 확인한다.
- `-W -Wall` 경고를 새로 늘리지 않는다. 수정한 파일의 신규 경고는 0건.
- 최신 gcc에서 error로 승격되는 항목(`implicit-function-declaration`, `int-conversion` 등)은 `make/platform.tools`의 `-Wno-error`에 의존한다. 신규 코드는 이 예외에 기대지 않는다.

### 안전성
- 버퍼 연산은 길이 지정 함수 사용(`snprintf`, `strncpy` 후 널 종료, `memcpy` 길이 검증).
- 외부 입력(소켓, 시리얼, 파일, CGI 인자)은 길이·범위 검증 후 사용.
- 반환값 검사: `malloc`, `fopen`, `read`/`write`, `socket` 계열.
- 장시간 실행 데몬: 자원(fd, 메모리) 해제 경로 확인. watchdog 갱신을 막는 블로킹 호출 금지.
- 인증정보(계정, 비밀번호, 키)를 소스에 새로 하드코딩하지 않는다. 로그에 출력하지 않는다.

### 하드웨어 의존
- `wan_led`(libfahw), GW의 wiringPi·SPI(SC16IS752) 등 하드웨어 접근 코드는 보드 없이 검증 불가. task에 "보드 미확인" 명시.
- 하드웨어 접근부는 얇은 함수로 분리해 테스트 시 대체 가능하게 한다.

## 소스 관리
- 수정은 `e3dp.2.1/` 로컬 소스에서만. 장치에서 직접 편집 금지.
- 날짜·접미사가 붙은 보관 폴더와 `*_org`, `*.old` 사본은 만들지 않는다. 이력은 git으로 관리. (기존 보관본은 2026-10-26 삭제, 백업은 `C:\ges\project\08_dp\_backup\`, 내역은 task 009)
- 파일·폴더 삭제 전 프로젝트 폴더 밖에 백업한다. 삭제 근거(Makefile 대상, 장치 빌드 결과, 기준 장치 사용 여부)를 task에 기록.
- 빌드 산출물(`*.o`, `*.a`, `*.cgi`, 배포 `*.tar`)은 커밋하지 않는다(`.gitignore` 기준).
- 버전 변경은 `make/platform.tools`의 `VER_TEXT`, `VER_BUILD_DATE`. 사용자 지시 없이 변경 금지.
- 기능·동작 변경 시 `수정이력.txt`에 날짜, 대상 모듈, 내용을 한 줄 추가.
- 커밋 메시지: 한 줄 요약(명사형) + 필요 시 본문. 커밋은 사용자가 요청할 때만.

## 작업 완료 기준
- [ ] 보드에서 `sudo make clean all` 성공, 빌드 기준값 이내 (기준값: 스킬 `e3dp-build`)
- [ ] 관련 테스트 추가·통과 (`pytest -m "not device and not ref"` 전체 통과)
- [ ] 보드 필요 항목은 실행 결과를 task에 기록. 미실행이면 "미확인" 명시.
- [ ] `수정이력.txt` 갱신(해당 시)
- [ ] task 체크리스트·상태 갱신

## 장치 조작 주의
- 보드·기준 장치에서 재부팅, 파티션/이미지 쓰기, 패키지 제거, 설정 파일 덮어쓰기 전에 사용자 확인.
- 기준 장치는 읽기 전용으로만 사용(허용 범위: 스킬 `e3dp-ref-device`).
- 현장 납품 장치에는 접속·명령 실행 금지. 대상은 보드와 기준 장치로 한정.
- 시리얼 포트는 사용 후 닫는다.
- 접속 정보는 스킬(`e3dp-build`, `e3dp-ref-device`)에만 둔다. 이 파일·task·테스트 코드에 복사하지 않는다.

## 범위 밖
- 실행 프로그램 자체의 보안 개선(프로토콜 암호화, 평문 비밀번호 로그, 하드코딩 FTP 계정 등)은 별도 task로 분리. 현 작업 중 발견하면 task "결정/미정"에 기록만 하고 수정하지 않는다.
