# 007 구 장치 비교 테스트
목표: 같은 입력을 기준 장치와 보드에 보내 응답 구조를 비교하고 시뮬레이터 완성도를 검증한다.
상태: 진행중 (기준 장치 실행 대기)

## 선행
- 002 캡처, 004 Host 시뮬레이터, 005·006 시뮬레이터

## 사실 (확인된 것만)
- 기준 장치는 연구소 보관 장치(현장 운영 아님). 현재 읽기 전용 요청만 허용. 설정 변경·재기동은 사용자 승인 후.
- 기준 장치에 실제 현장 통신이 없으므로 시뮬레이터 응답을 캡처로 검증할 수 없음. 시뮬레이터는 소스 기반 입력 생성기이고, 기대값은 "같은 소스를 구 OS에서 실행한 DP의 응답".
- 기준 장치의 값은 실시간으로 변함. 비교 대상은 프레임 구조(길이, 헤더, 필드 위치, 체크섬)이고 값·시각은 제외.
- 소스는 기준 장치 배포본(03.01.14)과 동일. 차이는 환경(컴파일러, libc, 커널, 보드) 차이로 해석.
- 해석 표

| 구 장치 | 신 보드 | 해석 |
|---|---|---|
| 통과 | 통과 | 시뮬레이터가 실제 동작을 재현할 가능성이 높음 |
| 실패 | 통과 | 시뮬레이터가 소스 해석에 치우침 → 시뮬레이터 수정 |
| 통과 | 실패 | 신 환경 차이 → 이식 이슈 후보 |
| 실패 | 실패 | 시뮬레이터 오류 |

## 방식 (소스 기반 시뮬레이터 + 구/신 DP 동일 입력)
1. 시뮬레이터(Host, GW, 정류기)를 소스 기준으로 작성(task 004~006).
2. 신 보드의 DP에 연결해 테스트.
3. 같은 시뮬레이터를 기준 장치의 DP에 연결해 같은 시나리오 실행. 이를 위해 기준 장치의 GW 주소 설정(`gw_list`, `nelite.db`)을 PC로 바꾸고 `modbus_server` 재기동 필요(사용자 승인 필요, 작업 후 원복).
4. 두 DP의 응답·상태(LPORT 값, 경보, 송신 프레임)를 비교.
- 효과: 시뮬레이터 오류가 양쪽에 똑같이 들어가므로 비교 결과에서 상쇄됨. 차이는 DP·환경에서 온 것.
- 한계: 시뮬레이터가 현실과 다른 입력은 양쪽 모두 검증하지 못함(소스 해석 오류는 잔존).

## 사고 기록 (2026-10-26 1차 실행)
- 현상: 1차 실행에서 모듈 종료 시 복원 중 SFTP 연결이 끊기고(PC와 구 장치 사이 간헐적 핑 손실 확인), 시험용 DP가 남은 채 중단됨. 구 장치는 재부팅되지 않음(가동 185일 유지).
- 원인 1: 백업·복원이 모듈마다 반복됨. 복원 중 끊기면 다음 모듈의 백업이 이미 바뀐 파일(또는 0바이트 파일)로 덮어써짐. 실제로 `nelite.conf` 백업이 0바이트가 됨.
- 원인 2: 복구 확인을 `ps` 인자 `/opt/e3dp/bin`으로 했는데, 상대 경로(`./smm`)로 기동한 `smm`·`acon_agent`는 인자가 달라 "없는 것"으로 오판. 그 사이 `smm`을 중복 기동함(수동 복구 중 발생, 정리 완료).
- 복구: `fixtures/ref_220/`의 원본으로 설정 5개 복원(해시 일치), `smm`·`acon_agent`를 절대 경로로 한 번씩 기동. 프로세스 목록 17개 일치, 서버 포트 6개 listen, 가동 시간 연속 확인.
- 조치: 백업은 세션 시작 1회(크기 검증, 임시 파일로 받아 교체), 복구는 세션 종료 1회 + 프로세스 목록 일치 검증(`ref_guard` fixture). SFTP 재연결·재시도 추가. 절대 경로 + `setsid`로 기동.
- 교훈: 복구 확인은 프로세스 이름 기준으로 하고, 백업 파일 크기를 검증한다.

## 결과 요약
| 항목 | 구 장치 | 신 보드 |
|---|---|---|
| GW 폴링 요청 형식(12바이트, func 3, count 120) | 통과 | 통과 |
| 포트별 요청, txid 증가 | 통과 | 통과 |
| AI 값 반영(0, 12.5, -3.25, 35.999) | 통과 | 통과 |
| 상/하한 상태 판정 | 통과 | 통과 |
| 12바이트 응답 → COMM_ALARM, 복귀 | 통과 | 통과 |
| 통신 이상 플래그 → COMM_ALARM | 통과 | 통과 |
| 길이 불일치·port 불일치 응답 무시 | 통과 | 통과 |
| 무응답·연결 거부에서 DP 유지 | 통과 | 통과 |
| 시각 동기(기동 직후 1회) | 건너뜀 | 건너뜀 |
- 건너뜀: 첫 루프에서 상위 GW 상태가 아직 COMM_ALARM이라 시각 동기가 전송되지 않는 기동 경쟁. 양쪽 환경에서 같은 방식으로 나타남.
- 해석: 이 범위(GW 폴링·값 반영·이상 응답)에서는 컴파일러·libc·커널·보드 차이가 동작에 영향을 주지 않음. 시뮬레이터가 소스 해석에 치우쳤더라도 양쪽에 똑같이 적용되므로 이 비교로는 드러나지 않음.
