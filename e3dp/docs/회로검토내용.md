# E3-DP 메인보드 회로 검토 내용

> 대상: E3-DP 메인보드 회로도 `docs/EIII-DP_MB_170315.pdf` (6쪽, 2017.01 작성, 작성 도면 날짜 2017-04-12)
> 목적: 회로도의 NanoPi 연결 핀(J3)과 소스(`wan_led`, `DPTester`)가 쓰는 GPIO를 대조해 두고, 신규 OS(Debian 13)에서의 하드웨어 접근 조건을 정리한다.
> 확인 방법: 회로도는 PDF를 렌더링해 직접 읽었다. 장치 값은 시리얼 콘솔(COM71, 115200)로 **읽기 전용 명령**만 실행해 얻었다(2026-11-03).
> 상태 표기: **확인** = 회로도·장치·소스로 직접 확인함 / **추정** = 근거로부터 계산·추론함 / **미확인** = 확인하지 못함.

## 2. J3 핀 연결표

NanoPi NEO 24핀 헤더(홀수 핀 = 한쪽 열, 짝수 핀 = 다른 쪽 열) 기준이다. GPIO 번호는 H3 `포트×32 + 핀`(A=0, C=64, G=192)이며, 신규 OS 커널에서도 같은 번호 체계임을 장치에서 확인했다(§4).

| J3 핀 | 도면 신호 | H3 핀 | sysfs 번호 | 용도 | 소스에서의 이름 |
|---:|---|---|---:|---|---|
| 1 | NANO_3V3 | - | - | 3.3V | |
| 2, 4 | NANO_5V | - | - | 5V | |
| 3 | I2C0_SDA | PA12 | 12 | I2C (4.7K 풀업) | 소스에서 사용 안 함 |
| 5 | I2C0_SCL | PA11 | 11 | I2C (4.7K 풀업) | 소스에서 사용 안 함 |
| 6, 9, 14, 20 | GND | - | - | 접지 | |
| **7** | **LAN_RESET/** | PG11 | 203 | IP175D 스위치 리셋 (R149 `0/NC`) | `RST_IP175` |
| **8** | **RES0** | PG6 | 198 | 예약 | `GPIO_RSV0` |
| **10** | **RES1** | PG7 | 199 | 예약 | `GPIO_RSV1` |
| **11** | **AX_RESET/** | PA0 | 0 | AX88772 리셋 (R7 33Ω) | `RST_ASIX` |
| **12** | **PWM1/GPIOA6** | PA6 | 6 | RUN/HALT LED 하트비트 (§3) | `LED_RUN` |
| **13** | **IP_MDC** | PA2 | 2 | IP175D 관리 인터페이스 클럭 | wan_led가 출력 LOW로 export |
| **15** | **IP_MDIO** | PA3 | 3 | IP175D 관리 인터페이스 데이터 | wan_led가 출력 LOW로 export |
| **16** | **W_LINK** | PG8 | 200 | WAN 링크 LED | `LED_WLAN_LINK` |
| **18** | **W_SPD** | PG9 | 201 | WAN 속도 LED (소스 이름은 ACT) | `LED_WLAN_ACT` |
| 17 | NANO_3V3 | - | - | 3.3V | |
| 19, 21, 22, 23, 24 | **미연결 (×)** | PC0·PC1·PA1·PC2·PC3 | 64·65·1·66·67 | 사용 안 함 | wan_led가 export 시도 |

- 핀 번호와 신호의 대응은 도면을 확대해서 읽은 것이다. 사람이 최종 확인한 것은 아니다.
- 표의 "H3 핀"과 sysfs 번호 중 핀 7, 8, 10, 11, 12, 13, 15, 16, 18은 NanoPi NEO(H3) 핀 배치와 장치의 `gpiochip` 정보로 확인했다. **I2C(핀 3, 5)와 미연결 핀(19, 21, 22, 23, 24)의 번호는 NanoPi NEO 핀 배치로부터 계산한 추정**이다.
- 리셋선(7, 11)은 3.3V로 풀업되어 있어, GPIO가 입력(기본값)이면 리셋이 걸리지 않는다.

### 소스와의 대조 결과 (확인)

- `wan_led`(`src/wan_led/gpio.c`)와 `DPTester`(`DPTester/gpio.c`)의 핀 정의(`RST_IP175` 7, `RST_ASIX` 11, `GPIO_RSV0` 8, `GPIO_RSV1` 10, `LED_RUN` 12, `LED_WLAN_LINK` 16, `LED_WLAN_ACT` 18)가 도면과 모두 일치한다.
- `wan_led`가 13, 15(MDC/MDIO)와 미연결 핀(19, 21, 22, 23, 24)을 시작할 때 출력 LOW로 export하는 것은 이전 OS에서와 같은 동작이다. 도면상 19, 21, 23, 24는 미연결이므로 export에 실패해도(커널 로그 `invalid GPIO -1`) 영향이 없다.
- 13, 15가 IP175D의 관리 인터페이스 신호인데 `wan_led`가 이를 출력 LOW로 고정한다. 이 신호를 다른 프로그램이 사용하는지는 **미확인**이다(이전 OS와 같은 동작이라는 것만 확인함).

## 3. RUN/HALT LED 하트비트 회로

```
PA6 (J3 핀 12) ── R93 0Ω ──> 74HCT123 U13A  A 입력
                              REXT/CEXT = R89 510K + C97 1µF (DVDD_3V3 풀업)
                              Q  ──> HALT_LED  (R91 10K 풀업)
                              /Q ──> RUN_LED   (R92 10K 풀업)
                              LM1 (듀얼 LED, 470Ω 직렬)
```

- `74HCT123`은 재트리거 가능한 단안정 멀티바이브레이터다. 입력 PA6에 펄스가 계속 들어오면 출력이 유지되고, 입력이 멈추면 시정수만큼 지난 뒤 출력이 반전한다.
- 시정수는 `R89 × C97 = 510kΩ × 1µF`이며, 데이터시트의 일반 공식(약 `0.45 × R × C`)으로 추정하면 **약 0.2초**다(추정).
- `wan_led`는 15ms 주기(`src/wan_led/wanled_main.c`의 타이머)로 PA6을 토글한다. 이는 시정수보다 훨씬 짧아 계속 재트리거되므로 `RUN_LED`가 켜진 상태로 유지된다.
- `wan_led`가 멈추면 약 0.2초 뒤 `HALT_LED`가 켜진다. 즉 `wan_led`는 단순 표시 프로그램이 아니라 **소프트웨어 정지를 하드웨어 표시로 알리는 하트비트** 역할이다.
- 장치에서 `wan_led` 실행 중 `gpio6`의 값이 0과 1로 번갈아 바뀌는 것을 확인했다. 물리 LED가 실제로 켜지는 것은 눈으로 확인하지 못했다(미확인).

WAN 링크·속도 LED(`W_LINK`, `W_SPD`)는 J9(10x2, LED 커넥터)로 나가며, 같은 커넥터에 스위치 포트별 `LINK0~3`, `SPD0~3`도 연결된다. `wan_led`는 `eth0`의 링크 상태(`SIOCETHTOOL`/`ETHTOOL_GLINK`)를 읽어 이 LED를 구동하고, `LED_ON`은 0(active-low)이다.

## 4. 신규 OS 장치 실측 (Debian 13)

| 항목 | 값 | 상태 |
|---|---|---|
| OS / 커널 | Debian 13 (trixie), `6.12.111+deb13-armmp`, armv7l | 확인 |
| sysfs GPIO | `CONFIG_GPIO_SYSFS=y`, `GPIO_CDEV=y`, `gpiochip0` base 0 (224개, `1c20800.pinctrl`), `gpiochip352` (32개, `1f02c00.pinctrl`) | 확인 |
| 번호 체계 | `포트×32+핀` (H3 sysfs 번호) | 확인 |
| 사용 핀 점유 | `wan_led`가 쓰는 핀(0, 1, 2, 3, 6, 64~67, 198~201, 203)은 커널이 점유하지 않음. PA10만 보드의 파란 LED가 사용 | 확인 |
| USB 이더넷 | 표준 `asix` 모듈로 `AX88772B`(`0b95:772b`)가 `eth1`로 동작, 100Mbps Full | 확인 |
| 콘솔 | `console=ttyS0,115200` (도면의 UART0 → MAX3232 RS232와 일치) | 확인 |
| 직렬/SPI 장치 | `/dev/ttyS0~4` 있음, `/dev/spidev*`·`/dev/ttyAMA*` 없음 | 확인 |
| 네트워크 | `eth0`(보드 내장, 10.10.1.100), `eth1`(ASIX, 192.168.123.2) | 확인 |

- UART2·SPI0에 해당하는 핀(11, 13, 15, 19~24)은 이 보드에서 GPIO로 쓰이거나 미연결이다. 따라서 이 보드에서 UART2와 SPI0을 켜는 설정은 쓸 수 없다. `/dev/spidev*`가 없는 현재 상태와 모순이 없다.

## 5. 신규 OS에서의 `wan_led` 문제와 조치 (장치에서 검증함)

| 항목 | 내용 |
|---|---|
| 문제 | 기존 `wan_led`가 쓰던 `libfahw`의 보드 인식은 `/proc/cpuinfo`의 `Hardware` 값이 `sun8i`로 시작해야 H3로 인식한다. 신규 OS의 값은 `Allwinner sun8i Family`라 인식에 실패해 `Fail to init board`로 종료했다. |
| 조치 | `libfahw` 의존을 없앴다(원본의 라이선스 미확인). `src/wan_led/gpio.c`가 `/sys/class/gpio`를 직접 쓰고, 헤더 핀 번호→sysfs 번호 표(`hdr2gpio`)를 소스에 포함한다. `DPTester`도 같은 방식이다. |
| 검증 | 장치에서 gcc 14.2로 빌드(링크는 `libc`만) 후 실행: `gpio1, 2, 3, 6, 198, 199, 200, 201`이 export·출력으로 설정되고(기준 장치와 동일) `gpio6`이 토글됨. 종료 후 모두 unexport로 원복함. 셸에서 sysfs로 LED를 하나씩 제어한 수동 테스트(W_LINK, W_SPD, 둘 다, RUN 하트비트, 하트비트 중단 시 HALT)가 시나리오대로 동작함을 육안으로 확인했다(2026-11-03). |

## 6. 이번 검토에서 확인하지 못한 것

- 회로도 3~5쪽(`IP175D` 스트래핑, MDI/변압기, `AX88772C`)은 부품·신호 이름까지만 읽었고 회로 동작은 검토하지 않았다.
- `IP175D` 관리 인터페이스(MDC/MDIO) 신호를 사용하는 소프트웨어가 있는지 확인하지 못했다.
- 이 문서는 **E3-DP 메인보드**만 다룬다. E3-RDP는 `/dev/ttyS1`, `/dev/ttyS2`, `/dev/spidev0.0`을 쓰므로 배선이 다르며, RDP 회로도가 필요하다.
