# E3-DP 메모리·파일 소스 연계표

> 대상: `e3dp.2.1` 소스. 경로는 `e3dp.2.1/` 기준이다.
> 목적: "어떤 메모리/파일이 무엇을 위해 있고, 어느 함수가 만들고, 누가 쓰는가"를 소스에서 바로 찾도록 정리한다.
> 구조체 크기·필드별 R/W 상세는 `공유메모리구조.md`에 있다. 이 문서는 **저장 방식별 분류와 생성 지점**만 다룬다.
> 확인 방법: 소스 줄을 직접 확인했다. "찾지 못함"은 `src`·`lib`·`include`를 grep한 결과 해당 코드가 없다는 뜻이다. 장비 배포본과의 일치는 확인하지 않았다.

## 1. 저장 방식 4종 한눈에 보기

| 분류 | 방식 | 휘발성 | 대표 대상 | 한 줄 요약 |
|---|---|---|---|---|
| A | SysV 공유 메모리 | 재부팅 시 소멸 | `DrDB`, `DrSI`, `shard_m` 등 19개 + `Proc` | 서버 간 실시간 데이터 공유. 파일 아님 |
| B | 파일 `mmap` | 파일에 남음 | `alarm.db` → `DR_ACB` | 경보 버퍼. 메모리처럼 쓰되 파일이 백업 |
| C | 일반 파일 (fopen) | 남음 | `nelite.conf`, `nelite.db`, `adr_*.rule`, `periodic/`, 로그 | 설정·구성 백업·이력·로그 |
| D | 커널/장치 파일 | — | `/proc/<pid>/status`, 시리얼, SRAM(미사용) | 프로세스 감시·HW 접근 |

- 같은 서버 안에서 A와 B가 함께 쓰인다 (예: `alarm_server`는 A 여러 개 + B).
- UDP/TCP 소켓은 데이터 저장이 아니라 통신이므로 이 문서에서 제외한다.

## 2. 공통 생성 함수 (A 분류)

| 함수 | 위치 | 동작 |
|---|---|---|
| `CreateSharedMemory(key, size)` | `lib/e3/e3lib.c:352` | `shmget(key, size, IPC_CREAT\|0666)` + `shmat`. 실패 시 `NULL` |
| `createShardMemory(key, size)` | `lib/gi_gw/shm.c:14` | 위와 같은 동작. `smm`, `acagent_checker`가 사용 |
| `init_shm(sname)` | `src/<서버>/init_shm.c` | 서버 기동 시 필요한 세그먼트를 `CreateSharedMemory`로 일괄 attach |

- 생성 주체는 **고정되어 있지 않다.** 먼저 기동한 프로세스가 `IPC_CREAT`로 만들고, 나머지는 같은 키로 붙는다.
- 서버 코드는 반환값 `NULL`을 검사하지 않는다.
- 키 정의: `include/nelite.h:108-127`, `Proc`만 `include/proc_watchdog.h:4`.
- `init_shm.c`가 있는 서버: main, db, control, alarm, emon, gw, modbus, netcheck, rect, rt, scan.
  `config`, `gather`, `realdata`, `acon_agent`는 서버 본문(`*_server.c`)에서 직접 호출한다.

## 3. 기능별 분류

### 3.1 설정·식별 (장비가 누구인지)

| 대상 | 방식 | 위치/키 | 생성·적재 지점 | 쓰는 쪽 |
|---|---|---|---|---|
| `netconfig` | A | `0xE3000001` | `main/init_shm.c:12` 생성 → `main/main_server.c:228-354`에서 `nelite.conf` 항목을 `get_arg1()`로 읽어 채움 | main |
| `nelite.conf` | C | `/opt/e3dp/conf/nelite.conf` (`nelite.h:74`) | 읽기: `main_server.c`. 쓰기: `util/config.c:148` | util(config 유틸) |
| `/etc/network/interfaces` | C | `util/config.c:15` | `util/config.c:174` | util |
| `/etc/hostname` | C | `util/config.c:16` | `util/config.c:201` | util |

- `netconfig`는 `main`만 쓰고 나머지는 읽기만 한다.
- `nelite.conf`에서 읽는 항목: WIRE_ID, WIRE_TYPE, HOST_NAME, MIH_IP/GATEWAY/NETMASK, PRIVATE_IP/GATEWAY/NETMASK, HOST_IP, ALARM_HOST_IP.

### 3.2 구성(설비 정의) DB — 가장 중요

| 대상 | 방식 | 위치/키 | 생성·적재 지점 | 쓰는 쪽 |
|---|---|---|---|---|
| `DrDB` (포인트 DB) | A | `0xE3000003` | 모든 서버 `init_shm()`에서 attach | db(적재), gw·rect·scan·control 등(값 갱신) |
| `DrSI` (장비 DB) | A | `0xE3000004` | 동일 | db, netcheck 등 |
| `raw_idx` (원시 인덱스) | A | `0xE3000010` | `db/init_shm.c:34`, `gw/init_shm.c:35` | 채움: db `ldb_handler.c:434-452`, 읽기: gw |
| `nelite.db` (구성 백업) | C | `/opt/e3dp/conf/nelite.db` (`nelite.h:76`) | 아래 흐름 참고 | db, config |

**`nelite.db` 저장·복원 흐름**
- 복원: `restore_db()` (`db/ldb_server.c:432`)
  - 호출: `ldb_server.c:261`. `DrDB`/`DrSI`가 비어 있을 때만 호출한다.
  - 성공하면 이어서 `create_raw_index()`와 `store_db()`를 실행한다.
- 저장(다운로드 시): `store_db()` (`db/ldb_decode.c:719`), 호출 `db/ldb_handler.c:215`
- 저장(상·하한/경보마스크 변경 시): `store_db()` (`config/config_handler.c:1474`), 호출 `:388`
  - 조건: `EC_SVC_UPDATE_LIMIT` 또는 `EC_SVC_ALARM_MASK`
- 파일 형식: 텍스트. `* Wire Info`, `* System Info`, `* Component Info`, `* Logicalport Info`, `* Point Info` 절 구분 (`restore_db` 파싱)
- 주의: `store_db`가 **두 파일에 같은 이름으로 따로 정의**되어 있다 (db 서버용, config 서버용).

### 3.3 실시간 상태 (설비 현재값·판정)

| 대상 | 방식 | 키 | 용도 | 쓰는 쪽 |
|---|---|---|---|---|
| `MAIN_ON_OFF_FLAG` | A | `0xE3000011` | 입전 확정(1)/정전·복구 대기(0) | scan |
| `VCB_FLAG` | A | `0xE3000012` | VCB OFF 또는 UV 시 1 | scan |
| `MAIN_VCB_FLAG` | A | `0xE3000013` | 서버 로직 미사용 (emon 출력만) | — |
| `MAIN_VCB_FLAG_COUNT` | A | `0xE3000014` | 입전 복귀 지연 카운트(8→0) | scan |
| `MAIN_GEN_FLAG` | A | `0xE3000015` | 발전기 종합 가동 | scan |
| `MAIN_GEN_FLAG1~3` | A | `0xE3000016~18` | 발전기 #1~#3 | scan |
| `MAIN_GEN_FLAG4` | A | `0xE3000019` | 발전기 #4 | scan |

- 생성: 각 서버 `init_shm.c`의 `// (11~18) VCB/GEN Flag` 블록 (예: `main/init_shm.c`). 각 1바이트.
- `MAIN_GEN_FLAG4`는 `scan`, `gw`만 attach한다.
- 상시 변하는 포인트 현재값은 이 플래그가 아니라 **`DrDB->lport[]`** 에 있다 (3.2).

### 3.4 이력·경보 (쌓이는 데이터)

| 대상 | 방식 | 키/경로 | 생성·적재 지점 | 쓰는 쪽 |
|---|---|---|---|---|
| `DrPCB` 정시 버퍼 | A | `0xE3000005` | `db`, `alarm`, `gather` init | gather |
| `PeakDB` 피크 | A | `0xE3000006` | `db`, `gw`, `control`, `alarm`, `gather` | gather, gw |
| `DcdsDB` DCDS 이력 | A | `0xE3000007` | `control`, `alarm`, `gather` (`rect`는 attach 없음) | gather |
| `UpsDB` UPS 이력 | A | `0xE3000008` | `alarm`, `gather` (`gw`는 attach 없음) | gather |
| **`DR_ACB` 경보 버퍼** | **B** | `/opt/e3dp/conf/alarm.db` (`nelite.h:78`) | 아래 흐름 참고 | alarm (emon은 `alarm init` 시) |
| `periodic/` 정시·피크 파일 | C | `/opt/e3dp/periodic` (`nelite.h:79`) | 아래 참고 | gather |

**`alarm.db` → `DR_ACB` 흐름 (유일한 B 분류)**
- 진입 함수: `open_alarm_db(ALARM_DB_PATH, sname)`
  - 정의: `alarm/init_shm.c` (fopen `:88`, `mmap` `:110`), 호출: `alarm/alarm_server.c:72`
  - emon 쪽 정의: `emon/init_shm.c` (fopen `:72`, `mmap` `:93`), 호출: `emon/emon.c:56`
- 순서
  - ① 파일 크기가 `sizeof(DrAlarmRec_ACBRec)`와 다르면 `fopen("w+")`로 새로 만든다.
  - ② `mmap_open()`으로 연다: `O_RDWR|O_CREAT|O_SYNC|O_NDELAY` (`alarm/mmap_addr.c:14`, `emon/mmap_addr.c:47`).
  - ③ `mmap(PROT_READ|PROT_WRITE, MAP_SHARED)`로 `DR_ACB`에 매핑.
  - ④ alarm은 이어서 `DrAlarmACBInitialize()`를 호출 → **기동마다 ACB를 비운다.**
- SysV 키 `SHM_DR_ACB_KEY(0xE3000009)`는 정의만 있고 attach 호출은 주석 처리 (`init_shm.c`의 `// (9)`).
- 32/64비트 전환 시 구조체 크기가 달라져 `alarm.db`가 새로 만들어진다.

**`periodic/` 파일**
- 정리: `PeriodFile_Delete_Check(del_day)` (`gather/gather_server.c:1778`), 호출 `:320`
  - 크기 0 파일 삭제, 수정 후 `del_day`일 초과 파일 삭제.
- Host 응답 후 삭제: `process_response()` (`gather_server.c:1759`)가 `remove(fname)`.
- **파일을 만드는 코드는 `src`/`lib`에서 찾지 못함.** 20건씩 저장한다는 설명은 `src/gather/README:7`에만 있다. 생성 경로는 별도 확인이 필요하다.

### 3.5 프로세스 감시 (살아있는지)

| 대상 | 방식 | 키/경로 | 생성 지점 | 쓰는 쪽 |
|---|---|---|---|---|
| `shard_m` | A | `0xE3000002` | 각 서버 `init_shm.c` | 각 서버가 자기 슬롯(`cnt_`, `kill_`, `ver_`), `smm`이 읽음 |
| `Proc` | A | `0xE000002` (자릿수 다름) | `acagent_checker/proc_check.c:389` 생성 + `memset 0` (`:391`) | acon_agent (`cnt_acon`) |
| `Proc` attach | A | 동일 | `acon_agent/acon_server.c:73` (`memset` `:74`) | — |
| `/proc/<pid>/status` | D | `/proc` | 읽기: `smm/smm_new.c:104-115`, `acagent_checker/proc_check.c:79-90,148-159`, `lib/gi_gw/pid.c:54-63` | smm, acagent_checker |

- 감시 대상이 둘로 나뉜다: `smm`은 `shard_m`, `acagent_checker`는 `Proc`을 본다.
- `acon_agent`의 `Proc` attach는 `memset`으로 **0 초기화를 다시 한다** (`acon_server.c:74`).
  `acagent_checker`가 만든 값도 지워지므로 기동 순서에 따라 의미가 있다.

## 5. 확인 필요 항목 (소스에서 찾지 못한 것)

- `periodic/` 파일을 **생성하는** 코드
- `adr_off.rule`, `adr_on.rule`을 **쓰는** 코드
- `emon`의 SRAM mmap 함수를 호출하는 곳 (미사용으로 보임)
- 웹 CGI용 세그먼트 `0x1000000`은 `cgi-bin/common.c`가 따로 만든다 (`src`의 서버는 미사용, 이 문서 제외)
